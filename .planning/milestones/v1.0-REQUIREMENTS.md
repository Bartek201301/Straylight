# Requirements: StrayLight Refactor & Cleanup

**Defined:** 2026-02-16
**Core Value:** Zero functional regression while reducing codebase complexity and clutter

## v1 Requirements

Requirements for this refactor milestone. Each maps to roadmap phases.

### Pre-Flight

- [ ] **PRE-01**: Establish baseline build metrics (build time, bundle size, file count)
- [ ] **PRE-02**: Verify existing lint/format automation works (ESLint, Prettier, Husky, lint-staged)
- [ ] **PRE-03**: Audit environment variables — ensure no secrets exposed, .env files gitignored
- [ ] **PRE-04**: Document current folder structure as migration reference

### Dead Code Elimination

- [ ] **DEAD-01**: Run Knip analysis to identify unused files, exports, and dependencies
- [ ] **DEAD-02**: Remove unused TypeScript/JavaScript files (components, utils, services not imported anywhere)
- [ ] **DEAD-03**: Remove unused exports from files that are otherwise still in use
- [ ] **DEAD-04**: Remove clearly unused npm dependencies from package.json
- [ ] **DEAD-05**: Remove commented-out code blocks that are clearly obsolete

### Scratchpad & File Cleanup

- [ ] **CLEAN-01**: Identify and delete scratchpad markdown files (temporary notes, completed task lists, deprecated plans)
- [ ] **CLEAN-02**: Preserve whitelisted files (hidden dirs, core docs, tool configs per PROJECT.md)
- [ ] **CLEAN-03**: Remove obsolete root-level files (stale SQL scripts, test files, temp artifacts)
- [ ] **CLEAN-04**: Clean up LIGHTTOOL_IMPLEMENTATION/ directory if obsolete
- [ ] **CLEAN-05**: Remove the old `aplikacja/` directory remnants (already deleted in git status)
- [ ] **CLEAN-06**: Clean up `performance-tasks/` and `.taskmaster/` if obsolete

### Folder Restructure

- [ ] **STRUCT-01**: Reorganize src/ to follow Next.js 14 App Router best practices with route groups
- [ ] **STRUCT-02**: Colocate route-specific components with their pages (private `_components` folders)
- [ ] **STRUCT-03**: Organize shared components into logical groups (ui/, layout/, features/)
- [ ] **STRUCT-04**: Structure lib/ with clear separation (services/, utils/, types/, hooks/)
- [ ] **STRUCT-05**: Standardize import paths to use `@/` aliases consistently
- [ ] **STRUCT-06**: Update all import references after file moves — zero broken imports

### Database & Migration Cleanup

- [ ] **DB-01**: Audit supabase/migrations/ for redundant or obsolete migration files
- [ ] **DB-02**: Remove root-level SQL files that are duplicated in migrations or no longer needed
- [ ] **DB-03**: Verify all migrations still apply cleanly after cleanup

### Performance Optimization

- [ ] **PERF-01**: Optimize server/client component boundaries — push "use client" directives down the tree
- [ ] **PERF-02**: Implement proper code splitting for heavy components (TipTap editor, admin dashboard)
- [ ] **PERF-03**: Audit and optimize bundle size — best-effort reduction via code splitting, dynamic imports, and asset compression
- [ ] **PERF-04**: Review and optimize image/font usage (next/image, next/font)
- [ ] **PERF-05**: Add proper loading.tsx and error.tsx files for route segments

### Validation

- [ ] **VAL-01**: npm run build passes with zero errors
- [ ] **VAL-02**: npm run lint passes with zero errors
- [ ] **VAL-03**: All existing tests pass
- [ ] **VAL-04**: No new TypeScript errors introduced
- [ ] **VAL-05**: Verify all routes still render correctly (no 404s or blank pages)
- [ ] **VAL-06**: Verify authentication flows still work (login, logout, role-based access)
- [ ] **VAL-07**: Bundle size does not increase from baseline

## Out of Scope

| Feature                                     | Reason                                            |
| ------------------------------------------- | ------------------------------------------------- |
| New functional features                     | Violates zero-functional-change rule              |
| UI/UX redesign                              | Visual changes require separate project           |
| Database schema changes                     | Data migrations are risky, separate scope         |
| Framework version upgrade (Next.js 15/16)   | Two simultaneous changes = hard to isolate issues |
| Dependency replacement (swapping libraries) | API changes = functional changes                  |
| Complete test coverage                      | Never-ending goal, defer to v2                    |
| Performance rewrites                        | Functional change disguised as refactor           |
