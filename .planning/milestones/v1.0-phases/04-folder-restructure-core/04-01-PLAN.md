Output: All page routes organized into audience-based route groups with build passing after each group move.
</objective>

  <action>
Move routes into four audience-based route groups incrementally. Use `git mv` for all moves to preserve history. Run `npm run build` after each group to catch issues early.

**IMPORTANT**: Root-level files that must NOT move (stay in src/app/):

- layout.tsx (root layout)
- error.tsx (root error boundary)
- not-found.tsx (root 404)
- globals.css
- robots.ts
- sitemap.ts
- api/ (entire API directory stays flat)

**Step 1: (marketing) group** — public pages, no auth required.

```bash
mkdir -p src/app/(marketing)
git mv src/app/about src/app/(marketing)/about
git mv src/app/articles src/app/(marketing)/articles
git mv src/app/library src/app/(marketing)/library
git mv src/app/cookies src/app/(marketing)/cookies
git mv src/app/privacy src/app/(marketing)/privacy
git mv src/app/terms src/app/(marketing)/terms
git mv src/app/quiz src/app/(marketing)/quiz
git mv src/app/suggest-resource src/app/(marketing)/suggest-resource
git mv src/app/page.tsx src/app/(marketing)/page.tsx
```

For profile: `/profile/[handle]` is public but `/profile` (own profile) requires auth. Research recommends keeping both in (marketing) since `/profile` handles auth client-side. However, the user's CONTEXT says (dashboard) is for logged-in users. Split them:

```bash
# Public profile view stays in marketing
mkdir -p src/app/(marketing)/profile
git mv src/app/profile/[handle] src/app/(marketing)/profile/[handle]
```

Run `npm run build` to verify marketing group.

Run `npm run build` to verify admin group.

**Import path note**: Since all imports use `@/` alias (maps to `./src/*`), and the moved files still live under `src/app/`, no imports FROM these page files change. Only relative imports between files within the same route might need updating, but since we're moving entire directories (not splitting them), relative imports between siblings (e.g., `./ArticleContent` in articles/[slug]/page.tsx) are preserved.

**Profile split**: After splitting profile into (marketing)/profile/[handle] and (dashboard)/profile/page.tsx, verify that no relative imports break. Check if profile/page.tsx imports from profile/[handle]/ or vice versa — if so, convert to @/ absolute imports.
