<task type="auto">
  <name>Task 1: Create rerunnable metrics collection script</name>
  <files>scripts/collect-metrics.js</files>
  <action>
Create `scripts/collect-metrics.js` — a Node.js script that collects all baseline metrics and outputs to both JSON and Markdown.

The script must:

1. **Collect these metrics:**
   - `sourceFileCount` — count of `.ts` and `.tsx` files in `src/`
   - `sourceDirectoryCount` — count of directories in `src/`
   - `totalLOC` — total lines of code in `.ts` and `.tsx` files in `src/`
   - `productionDependencies` — count from package.json `dependencies`
   - `devDependencies` — count from package.json `devDependencies`
   - `routeCount` — count of `page.tsx` and `route.ts` files in `src/app/`
   - `typescriptErrors` — count from `npx tsc --noEmit 2>&1` (parse "error TS" occurrences)
   - `eslintWarnings` — count from `npx next lint 2>&1` (parse warning count from summary line)
   - `eslintErrors` — count from lint output (parse error count from summary line)
   - `circularDependencies` — count from `npx madge --circular --ts-config tsconfig.json --json src/` (parse JSON array length)
   - `buildTimeMs` — time `npx next build` (delete `.next/` first for cold build measurement)
   - `collectedAt` — ISO timestamp

2. **Platform compatibility:**
   Use Node.js `fs` and `path` modules with `child_process.execSync` for commands. Use `path.join` for all file paths. For file counting, use Node.js `fs.readdirSync` recursively instead of Unix `find` commands — this ensures Windows compatibility.

3. **Output:**
   - Write JSON to `.planning/metrics/baseline.json` (create directory if needed)
   - Write Markdown to `.planning/metrics/baseline.md` with a formatted table
   - The Markdown should include:
     - Title: "# Baseline Metrics — Phase 1"
     - Collection timestamp
     - Table with metric name, value, and notes
     - Section noting measurement conditions (cold build, machine type info optional)

4. **Error handling:**
   - Wrap each metric collection in try/catch
   - If a metric fails to collect, set its value to `null` with an error note
   - Script should never crash — partial metrics are better than no metrics
   - Print progress to console as each metric is collected

5. **Rerunnable design:**
   - Accept optional `--output-prefix` argument for naming (default: `baseline`)
   - This allows running `node scripts/collect-metrics.js --output-prefix post-phase-2` after Phase 2
   - Always overwrite the specified output file (not append)

Do NOT use Unix-specific commands (`find`, `wc -l`, `tail`). Use Node.js APIs for all file operations to ensure Windows compatibility.
Do NOT run the build step with `ANALYZE=true` — that's a separate operation.
</action>

<task type="auto">

1. Ensure `.planning/metrics/` directory exists:
   ```bash
   mkdir -p .planning/metrics
   ```

2. Run the metrics collection script:

   ```bash
   node scripts/collect-metrics.js
   ```

   This will take several minutes due to the build step. It creates both `baseline.json` and `baseline.md`.

3. Verify the outputs:
   - Check `baseline.json` has all expected keys and non-null values
   - Check `baseline.md` has the formatted table

4. Run bundle analyzer to generate per-page HTML reports (separate from metrics script):

   ```bash
   cross-env ANALYZE=true npx next build
   ```

   On Windows without cross-env in PATH: `npx cross-env ANALYZE=true next build`
   This generates HTML reports in `.next/analyze/` — these are interactive treemaps.
   Copy the HTML reports to `.planning/metrics/` for reference:

   ```bash
   cp .next/analyze/*.html .planning/metrics/ 2>/dev/null || echo "No analyzer HTML found"
   ```

   Note: If the analyze build fails or no HTML is generated, document it as a known issue but do not block the plan. The JSON/Markdown metrics are the primary deliverable.

5. Review baseline.md and verify metrics are reasonable:
   - Source files should be ~407

   - TS errors should be 0
   - ESLint errors should be 0, warnings ~394
   - Route count should be ~100

6. Print a summary of the baseline to console for the plan summary.
