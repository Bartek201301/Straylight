<task type="auto">
  <name>Task 1: Compress oversized static assets in public/</name>
  <files>scripts/compress-assets.js</files>
  <action>
1. **Audit oversized files** in `public/`:
   ```bash
   find public/ -type f -size +500k | sort -rn
   ```
   The research identified these oversized files:
   - `sztucznainteligencja.jpg` (6.1MB) -- compress to ~200KB
   - `placehold1.svg` (4.5MB) -- if it's a complex SVG, consider whether it can be simplified or converted to WebP/PNG
   - `quantiumcomputing.jpg` (3.9MB) -- compress to ~200KB
   - `logo transparent.png` (2.0MB) -- compress to ~100KB
   - `etycznedylematyaizmedycyna.png` (1.5MB) -- compress to ~150KB
   - `avatar-chatbota.png` (1.4MB) -- compress to ~100KB
   - `medycynaai.png` (1.2MB) -- compress to ~150KB
   - `aboutpage/*.svg` (11MB total, 5 files) -- evaluate if SVGO can reduce size

2. **Check existing compression scripts** (`scripts/optimize-images-simple.js`, `scripts/optimize-images.js`, `scripts/compress-assets.js`) to see if they work. If a usable script exists, run it. If not, use `sharp` (already installed) to compress images via a Node.js one-liner or by running/updating the existing script.

3. **Compress JPEG/PNG files** using sharp:
   - JPEGs: quality 80, progressive
   - PNGs: quality 80, progressive
   - Target: no image file over 500KB (except SVGs which need different handling)

4. **Handle SVGs:**
   - For the 4.5MB `placehold1.svg`: Check if it contains embedded raster data. If so, it should be converted to WebP/PNG. If it's vector data, try SVGO optimization.
   - For `aboutpage/*.svg`: Same analysis. If they're 700KB-1MB each, SVGO may help. If they contain embedded images, flag but don't convert (would change format).
   - If SVGO is not installed and SVGs are complex, flag them in the summary for manual review rather than installing a new dependency.

5. **Important constraints:**
   - DO NOT change file names (would break references in components)
   - DO NOT change file formats unless creating a WebP alongside the original (components reference specific filenames)
   - Keep originals if format conversion is needed (backup to a temp dir, convert in-place)

6. Run `npm run build` to verify no broken image references.
   </action>
   <verify>
7. `find public/ -type f \( -name "*.jpg" -o -name "*.jpeg" -o -name "*.png" \) -size +500k | wc -l` returns fewer files than before
8. Total public/ directory size is significantly reduced from 60MB baseline
9. `npm run build` passes
   </verify>
